Device Preview

Side-by-side layout check across phone sizes. Standalone — nothing here touches the app.
What this can and can't tell you. This is good for layout, text wrapping, tap-target sizes and how much fits on screen. It cannot reproduce the header-hidden-behind-the-address-bar bug — that one comes from real iOS browser chrome overlaying the page's layout viewport, which no desktop preview (this page or Chrome DevTools) simulates. Only a real phone confirms that. The "show address-bar overlay" checkbox is a cosmetic stand-in to show roughly how much a real browser covers.

Chrome DevTools does the same job with more presets: F12, then Ctrl+Shift+M.

Base URL defaults to this page's own folder. If you point it at a different origin, the frames may show "Couldn't load the pool" — browsers can block sign-in storage inside a cross-origin iframe. That's the preview's limitation, not a fault in the app.
